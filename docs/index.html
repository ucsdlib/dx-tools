Quick start

Three paths, depending on where you're starting from. All produce the same result: a working tool with this design system in place.

New tool

Starting from scratch. Use starter/template.html and this repo's CSS/JS directly.

Existing tool

Retrofitting an existing project. Copy the design-system/ files in and add the imports.

With Claude

Using Claude Code to build or update a tool. Drop CLAUDE.md in your project root first.

New tool from scratch

The fastest path is to build directly inside this repo. Clone it, copy starter/template.html as your starting point, and remove the docs/ pages you don't need. Your tool's HTML files sit at the root alongside css/, js/, and fonts/ — no path adjustments needed.

bash
# Clone dx-tools and start fresh
git clone https://github.com/your-org/dx-tools your-tool-name
cd your-tool-name

# Start from the minimal template
cp starter/template.html index.html

# Wire up git for your new project
rm -rf .git
git init
git add .
git commit -m "init: new tool from dx-tools starter"

Alternatively, if you want to keep your tool in its own repo while sharing assets with other tools, use the sibling pattern: place your tool directory next to dx-tools/ and reference CSS with ../dx-tools/css/tokens.css. One copy of the fonts, shared by everything.

Retrofitting an existing tool

Copy the design system files into a design-system/ subdirectory in your existing project, then add the imports. This approach keeps the design system self-contained and easy to update by replacing those files.

bash
# From your existing project root
# Copy the core files from dx-tools
cp -r /path/to/dx-tools/css  design-system/css
cp -r /path/to/dx-tools/js   design-system/js
cp -r /path/to/dx-tools/fonts design-system/fonts

Then add this to your page <head> — adjust the path prefix to match where you placed the files:

html
<!-- FOUC prevention: must come first, before any stylesheet -->
<script>const t=localStorage.getItem('dx-theme');document.documentElement.setAttribute('data-theme',t||'light');</script>

<!-- Fonts and design system (adjust path prefix as needed) -->
<link rel="stylesheet" href="design-system/css/fonts.css">
<link rel="stylesheet" href="design-system/css/tokens.css">
<link rel="stylesheet" href="design-system/css/frame.css">
<link rel="stylesheet" href="design-system/css/components.css">
<link rel="stylesheet" href="design-system/css/preview.css">
<link rel="stylesheet" href="design-system/css/code.css">

<!-- Icons + theme toggle -->
<script src="design-system/js/lucide.min.js"></script>
<script src="design-system/js/theme.js" defer></script>
<script src="design-system/js/code-copy.js" defer></script>

Wrap your existing content in the frame layout shell to get the header, sidebar, and main area:

html
<body>
  <a href="#main" class="skip-link">Skip to main content</a>
  <div class="dx-doc-layout">
    <header class="dx-header" role="banner">
      <!-- your tool name + nav links here -->
    </header>
    <div class="dx-doc-body">
      <nav class="dx-sidebar" aria-label="...">
        <!-- optional sidebar nav -->
      </nav>
      <main id="main" class="dx-main">
        <!-- your tool content -->
      </main>
    </div>
  </div>
</body>

With Claude

When using Claude Code to build or update a tool, copy CLAUDE.md from this repo into your project root. Claude Code automatically reads it at the start of every session — it provides the token names, component class patterns, and accessibility rules without you having to re-explain the system each time.

bash
# Copy CLAUDE.md into your project
cp /path/to/dx-tools/CLAUDE.md your-project/CLAUDE.md

# Claude Code will now read it automatically.
# You can also edit it to add project-specific notes.

After copying, open Claude Code in your project directory and ask it to start building. Claude will already know the token names, component classes, HTML patterns, and ARIA requirements for this design system.
