Design system

Accessibility

Accessibility is a first-class design constraint, not an afterthought. This design system targets WCAG 2.1 Level AAA — beyond compliance to genuine usability for everyone.

Our target: WCAG 2.1 AAA

The campus brand guidelines require WCAG 2 Level AA (4.5:1 contrast for normal text). This design system exceeds that standard:

CriterionWCAG AAWCAG AAA (our target)
Normal text contrast (1.4.3 / 1.4.6) 4.5:1 7:1
Large text contrast (1.4.3 / 1.4.6) 3:1 4.5:1
Touch target size (2.5.5) — 44 × 44 px minimum
Focus visible (2.4.7 / 2.4.11) Visible 3 px, high contrast, offset
Non-text contrast (1.4.11) 3:1 3:1 minimum, targeting higher
Spacing (1.4.12) Text spacing overrideable No content loss at 2× line height
Note on AAA full compliance
Full WCAG 2.1 AAA compliance for an entire site is rarely achievable due to conflicting criteria. Our goal is AAA on all criteria where we have direct control — especially contrast, focus, touch targets, and semantic structure.

The four POUR principles

Perceivable
Information must be presentable in ways users can perceive
All non-text content has a text alternative. Color is never the sole means of conveying information. Text can be resized to 200% without loss of functionality.
WCAG 1.1, 1.3, 1.4
Operable
UI components must be operable by all users
All functionality is available from a keyboard. No time limits on interactions. No content that flashes more than 3 times per second. Skip links provided.
WCAG 2.1, 2.2, 2.3, 2.4, 2.5
Understandable
Information and UI must be understandable
Language declared in HTML. Errors identified clearly with instructions. Labels and instructions provided for all form inputs. Consistent navigation and labels.
WCAG 3.1, 3.2, 3.3
Robust
Content must be robust enough for assistive technologies
Valid HTML. ARIA used correctly and only when necessary. Name, role, and value exposed for all UI components. No ARIA that overrides native semantics without reason.
WCAG 4.1

Contrast requirements

All primary and muted text tokens meet AAA (7:1) on their intended backgrounds. Subtle text (--color-text-subtle) is AA only — use it exclusively for decorative, non-informational text.

Text roleTokenRequired ratioOur ratio
Body copy, labels--color-text7:1 (AAA)15–22:1 ✅
Secondary text--color-text-muted7:1 (AAA)7.5–9:1 ✅
Captions, decorative--color-text-subtle4.5:1 (AA)4.5–5:1 ✅
Minimum font size—14px bold or 18px regular14px minimum enforced ✅
Never use color as the sole differentiator
Error states, status indicators, trends, and link differentiation must always combine color with an additional cue — icon, underline, pattern, or text label. This satisfies WCAG 1.4.1.

Focus management

The design system provides a consistent focus ring via :focus-visible. It uses a 3 px outline at 2 px offset — visible on all backgrounds in both color modes.

css
/* Global focus — applies to all interactive elements */
:focus-visible {
  outline: 3px solid var(--color-focus);
  outline-offset: 2px;
  border-radius: var(--radius-sm);
}

/* Suppress for mouse users only */
:focus:not(:focus-visible) {
  outline: none;
}

Focus trapping in dialogs

When a <dialog> opens, focus must move to the first focusable element inside it. When it closes, focus returns to the triggering element. The native <dialog> element handles this automatically in modern browsers.

javascript
const trigger = document.getElementById('open-btn');
const dialog  = document.getElementById('my-dialog');

trigger.addEventListener('click', () => {
  dialog.showModal();   // native <dialog> traps focus automatically
});

dialog.addEventListener('close', () => {
  trigger.focus();      // restore focus to trigger on close
});

Skip link

Every page includes a skip link as the first focusable element. It becomes visible on focus (keyboard users only) and moves focus to #main.

html
<!-- First element in <body> -->
<a href="#main" class="skip-link">Skip to main content</a>

<!-- ... header, nav ... -->

<main id="main"> ... </main>

Screen reader guidance

ARIA roles — use sparingly

Use native HTML elements before reaching for ARIA. Every ARIA role, property, and state carries an implicit contract with assistive technologies — only use what you can fully implement.

PatternPreferred approachAvoid
Button <button> <div role="button"> — no keyboard support by default
Toggle switch <input type="checkbox" role="switch"> CSS-only toggle with no keyboard support
Live region (status) role="status" or aria-live="polite" aria-live="assertive" unless truly urgent
Icon buttons aria-label="Action name" Icon with no label — invisible to screen reader users
Decorative images alt="" Missing alt attribute — announced as file path
Tables <th scope="col/row"> Tables used for layout

Landmark regions

Every page must have exactly one <main>. Use semantic landmarks so screen reader users can navigate by region.

html
<header role="banner">
  <nav aria-label="Design system sections"> ... </nav>
</header>

<nav class="dx-sidebar" aria-label="Page navigation"> ... </nav>

<main id="main"> ... </main>

<footer> ... </footer>

Motion & animation

All transitions in this design system respect prefers-reduced-motion. When the user has requested reduced motion, all transitions are cut to 0.01ms — effectively instant with no animation.

css
/* In frame.css — applied globally */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration:       0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration:      0.01ms !important;
    scroll-behavior:          auto !important;
  }
}
Content shifts still happen
Removing transitions means state changes are instant, not invisible. display: none toggles, height changes, and dialog open/close still work — they just don't animate. Test your UI with reduced motion enabled to verify nothing breaks.

Pre-ship checklist

Run through this checklist before every release. Zero critical axe violations is the minimum bar — AAA on all primary text is the target.

  • Zero axe critical violations — Run axe DevTools or @axe-core/cli on every page. Zero criticals required to ship.
  • All primary text at 7:1 contrast — Verify with WebAIM Contrast Checker or browser DevTools.
  • Tab through every interactive element — Focus must be visible on every button, link, input, and control. Nothing should be unreachable by keyboard.
  • Skip link present and functional — Focus the page and press Tab once. The skip link must appear and work.
  • All images have alt text — Informational images: descriptive alt. Decorative images: alt="". No missing alt attributes.
  • All icon buttons have aria-label — Any button with only an icon (no visible text) must have aria-label.
  • Form inputs have visible labels — No placeholder-only labels. Every input has a <label> linked via for/id.
  • Error states use icon + color + text — Never color alone. Verify error messages are associated via aria-describedby.
  • Heading hierarchy is correct — One <h1> per page. No skipped levels (h1 → h3). Headings describe the content below them.
  • Touch targets ≥ 44 × 44 px — Verify in browser DevTools. Use padding to meet the minimum without enlarging the visual element.
  • Test with VoiceOver (macOS) or NVDA (Windows) — Keyboard + screen reader test. Navigate with VO+Tab and VO+Arrow keys.
  • Test with prefers-reduced-motion enabled — Enable in OS settings (macOS: System Settings → Accessibility → Reduce Motion). No broken layouts.
  • Zoom to 200% — no horizontal scroll on main content — Reflow (WCAG 1.4.10) requires no horizontal scroll at 320 CSS px width.

Automated tools catch ~30–40% of issues
No automated tool can verify that focus order is logical, that label text is meaningful, or that screen reader announcements make sense in context. Manual testing with a keyboard and screen reader is irreplaceable.
