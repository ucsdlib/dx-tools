Design system

Frame & Preview

Two distinct CSS scopes, one page. The frame is the tool chrome — navigation, controls, panels, status bars. The preview is brand-faithful UC San Diego content rendered inside a browser-chrome container. They share a token foundation but override each other deliberately.

Architecture

Every DX tool page has two layers. The frame layer provides the tool chrome: dark navy shell, Atkinson Hyperlegible, Turquoise/Blue accents. The preview layer is a scoped content canvas: white background, Roboto, brand-faithful UC San Diego palette.

Frame layer — .dx-frame
--color-bg #0d1b2e (dark)
--color-surface Navy
--color-accent Turquoise
--font-frame Atkinson Hyperlegible
Preview layer — .dx-preview
--brand-bg #FFFFFF (always)
--brand-navy UC San Diego Navy
--brand-blue UC San Diego Blue
--font-preview Roboto

The frame layer adapts to dark/light mode. The preview layer is always light — it represents the UC San Diego website as it actually appears to end users, and should never be inverted or recolored by the tool frame's mode.

Token boundary

Tokens are defined in tokens.css at the :root level. The .dx-preview class creates a token override scope — it re-declares the same token names with brand-faithful values. Content inside the preview inherits these overrides, not the frame values.

css
/* tokens.css — root defines frame values */
:root, [data-theme="light"] {
  --color-surface:    #FFFFFF;
  --color-accent:     #00629B;  /* UC San Diego Blue in light mode */
  --font-frame:       'Atkinson Hyperlegible', sans-serif;
}

/* tokens.css — .dx-preview overrides to brand-faithful values */
.dx-preview {
  --color-surface:    #FFFFFF;   /* same, but explicit */
  --color-text:       #182B49;   /* always Navy, never frame text */
  --color-accent:     #00629B;   /* same in light, but isolated from dark mode */
  font-family:        var(--font-preview); /* Roboto, not Atkinson */
  background-color:   #FFFFFF;
}

/* Dark mode frame does NOT affect preview — token override holds */
[data-theme="dark"] .dx-preview,
@media (prefers-color-scheme: dark) { .dx-preview } {
  /* tokens.css re-declares all --color-* inside .dx-preview to stay light */
}

Cascade rules

Because .dx-preview lives inside .dx-main, frame CSS rules can leak in if their specificity is too high. This system uses two techniques to prevent that:

1. :where() in frame.css

Frame link rules are wrapped in :where(), which contributes zero specificity to the selector. This means any preview rule with even one class wins.

css
/* frame.css — :where() zeroes out .dx-main's contribution */
:where(.dx-main) a:not(.btn) {
  color: var(--color-accent);  /* specificity: 0,1,1 */
}

/* preview.css — (0,2,0) safely wins */
.dx-preview .preview-nav__link {
  color: rgba(255, 255, 255, 0.9);  /* ✅ always wins */
}

/* Without :where() — frame rule would be 0,2,1 and WIN over preview nav */

2. Scoped selectors in preview.css

Every structural element in the preview that is also an <a> tag (nav links, brand link) uses a double-class selector to reach specificity 0,2,0+, safely above the frame rule.

Specificity reference

0,2,1 frame.css — .dx-main a:not(.btn) (without :where()) used to WIN
0,1,1 frame.css — :where(.dx-main) a:not(.btn) (current) neutral
0,1,1 preview.css — .dx-preview a (body content links) wins (later source)
0,2,0 preview.css — .dx-preview .preview-nav__link wins
0,2,0 preview.css — .dx-preview .preview-nav__brand wins

Rule for adding new preview elements

When adding a new structural element inside .dx-preview that contains an <a> tag (e.g. a footer link, a card link):

  • Use a scoped class selector: .dx-preview .your-component__link (0,2,0) — never just .your-component__link (0,1,0)
  • Always set text-decoration: none explicitly if the element should not have an underline
  • Never rely on specificity tricks alone — add a comment noting why the double-class is needed

Preview content types

The preview layer ships with several ready-made structural patterns for common UC San Diego page elements. Each is a CSS class that lives inside .dx-preview.

ClassPurposeNotes
.preview-nav Top navigation bar Navy background, white links, yellow active indicator
.preview-nav__brand Site name / logo link Bold white, no underline. Uses double-class selector for cascade safety.
.preview-nav__link Nav link item 90% white text (~15:1 on Navy ✅ AAA). .active adds yellow border.
.preview-gold-bar 4px Gold accent bar Key UC San Diego brand motif. Always renders below the nav.
.preview-hero Navy hero section Full-width Navy block with white heading and body text.

Adding custom preview content

Write any HTML inside .dx-preview. Headings, paragraphs, and links will automatically use brand-faithful styles. For nav or structural links, always use a scoped selector (at minimum .dx-preview .your-class) so it reaches specificity 0,2,0.

html
<!-- Minimal preview container -->
<div class="preview-container">
  <div class="preview-toolbar">
    <div class="preview-toolbar__dots" aria-hidden="true">
      <span class="preview-toolbar__dot"></span>
      <span class="preview-toolbar__dot"></span>
      <span class="preview-toolbar__dot"></span>
    </div>
    <span class="preview-toolbar__label">Preview</span>
  </div>
  <div class="dx-preview dx-preview--padded">

    <!-- Nav (always use .preview-nav__link for cascade safety) -->
    <nav class="preview-nav">
      <a href="#" class="preview-nav__brand">UC San Diego</a>
      <a href="#" class="preview-nav__link active">Home</a>
      <a href="#" class="preview-nav__link">About</a>
    </nav>
    <div class="preview-gold-bar"></div>

    <!-- Body content — headings, paragraphs, links use brand styles automatically -->
    <h1>Page title</h1>
    <p>Body text with a <a href="#">content link</a>.</p>

  </div>
</div>

Usage guide

When to use .dx-frame vs .dx-preview

ElementScopeReasoning
Header, sidebar, status bar.dx-frameTool chrome — part of the tool UI itself
Control panels, settings.dx-frameTool controls — Atkinson for readability
Alerts, badges, tables.dx-frameData display is part of the tool, not the preview
UC San Diego page content.dx-previewBrand-faithful representation of the actual site
Navigation mockups.dx-previewMust match UC San Diego brand exactly
Page templates, hero sections.dx-previewContent the end user will see on ucsd.edu

CSS file responsibilities

FileScopeResponsibility
tokens.cssGlobalAll design tokens. Defines both frame and preview token values. Single source of truth.
frame.css.dx-frame, .dx-mainTool chrome layout — header, sidebar, status bar, body typography. Uses :where() on context selectors to keep specificity low.
preview.css.dx-previewBrand-faithful content styles. All structural link selectors use double-class (0,2,0+) to win the cascade over frame rules.
components.cssSharedComponents that work in both layers (buttons, panels, badges). Inherits the active token scope.
